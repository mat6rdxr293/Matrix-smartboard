# Состояние ML-части — 28 сентября 2026

## Коротко

- **Что есть:** весь путь «PDF учебника → текст → параграфы → задания и слайды» работает на реальных учебниках,
  в том числе на казахском. Модель (Qwen3.5-4B, сжатая до 2.6 ГБ) запускается на процессоре без видеокарты
  и укладывается в память доски (~3 ГБ из 8).
- **Главный риск — время.** На ноутбуке разработчика урок (6 заданий + 6 слайдов) готовится за 4.5–7.5 мин.
  Процессор доски, скорее всего, в 2–3 раза слабее → **ожидаем 9–15 мин на урок**. Поэтому урок нужно
  готовить заранее в фоне и/или показывать текст по мере генерации.
- **Чего не хватает:** реального датасета для дообучения, замера на настоящей доске и финального
  контракта с бэкендом.

## 1. Что сделано

### Модель и окружение
- Базовая модель — **Qwen3.5-4B**: хорошо знает казахский и русский, есть режим «со зрением» для сканов.
  Запасной вариант — Qwen3.5-2B (в 2 раза быстрее, но чаще выдумывает факты).
- Для доски модель сжимается в **GGUF Q4_K_M** — один файл 2.6 ГБ (2B — 1.2 ГБ), запускается через llama.cpp
  (или Ollama).
- **Важная находка по памяти:** по умолчанию llama.cpp держит в памяти две копии весов (4.3 ГБ).
  С отключённым mmap — 2.8 ГБ при той же скорости. На доске запускать только так.
- Дообучение (QLoRA через Unsloth) работает целиком: обучение → слияние → GGUF → запуск на CPU.
  Проверено на 50 тестовых примерах. Обход бага Unsloth при слиянии — в `export_gguf.py`.

### Учебники
- Три учебника-скана с okulyk.kz: история Казахстана 11 (ru, 165 стр.), алгебра 11 ЕМН (ru, 254 стр.),
  физика 11 ЕМН (kk, 240 стр.).
- **Распознавание Tesseract** (так будет на доске): 6 / 12.5 / 13.7 мин на книгу — укладываемся
  в бюджет «~20 минут на загрузку». Обычный текст читается хорошо, формулы — плохо.
- **Разметка параграфов:** алгебра 28/28, физика 41/41, история 11/11 — без пропусков, хотя Tesseract
  портит знак «§».
- **Распознавание моделью со зрением** (на видеокарте, для обучения, а не для доски): физика целиком,
  240 страниц за ≈2 ч. Текст, таблицы и формулы в LaTeX — очень точно.
- **Исправлено сегодня:** язык русских учебников определялся как казахский (Tesseract вставляет в русский
  текст отдельные казахские буквы). Из-за этого урок по алгебре сгенерировался на казахском. Теперь язык
  определяется по доле казахских букв во всём параграфе, а латиница из формул не учитывается:
  80 из 80 параграфов — верно, есть тесты (`python -m unittest discover tests`).

### Урок по параграфу (главный сценарий доски)
- Учитель выбирает учебник и параграф → модель выдаёт **задания** (тесты с 4 вариантами, открытые вопросы,
  задачи; ответы и уровень 1–3) и **текст слайдов** (заголовок, тезисы, заметка учителю) в формате JSON.
- Защиты: JSON-схема (модель физически не может выдать неверную структуру), штраф за повторы,
  автопроверка на зацикливание и повтор с другим seed.
- Ускорение: текст параграфа идёт первым в обоих запросах, поэтому для слайдов он берётся из кэша сервера
  (читается 11–16 с вместо ~50–80 с).
- **Формат контракта v1:** состав заданий задаётся схемой (для параграфа с формулами — 3 теста, 2 открытых,
  1 задача с ходом решения); ответ теста всегда один из вариантов, варианты перемешаны; формулы — Unicode
  (LaTeX запрещён грамматикой).
- **Проверка математики (SymPy):** первообразные, интегралы, производные и арифметика в решениях.
  Ошибки модели исправляются автоматически (в уроке по алгебре: «x³ + C» для x² → «x³/3 + C»,
  «(2/3)x³» для 4x² → «4x³/3»). Физические формулы автоматически не проверяются — пометка «⚠️ проверьте».

### Качество (бенчмарк, 30 вопросов: история, биология, физика × kk/ru/en)

| Прогон | kk | ru | en | всего |
|---|---:|---:|---:|---:|
| без поиска | 58% | 83% | 94% | 77% |
| с поиском по текстам (RAG) | **75%** | 72% | **100%** | **82%** |

- Казахский — самый слабый язык, и именно ему поиск помогает сильнее всего (+17 п.п.).
- Падение русского с RAG в основном из-за эталонов: например, эталон по Конституции устарел.
- Оценки ставил LLM-судья (та же модель), совпадение с ручной проверкой ~26 из 30 → цифры предварительные.
- В уроках казахский грамотный, тесты осмысленные, формулы верные. **Расчётные задачи ненадёжны:**
  встречались неверные ответы и бессмысленные единицы — их нужно проверять (интерфейс помечает их ⚠️).

### Инструменты
- **Веб-интерфейс** (`python scripts/ui.py` → http://127.0.0.1:7860): данные → обучение → экспорт →
  проверка → урок, плюс вкладка с обзором, планом и калькулятором времени на доске.
- **Сервер для бэкенда:** OpenAI-совместимый API (`scripts/serve.sh`, описание в `docs/API_FOR_BACKEND.md`).
  Бэкенду достаточно поменять `base_url`.
- **Поиск по текстам (RAG):** эмбеддер e5-small, 20 мс на запрос — не узкое место.

## 2. Тайминги (ноутбук i7-13650HX, 4 потока — симуляция доски)

| Что | 4B | 2B |
|---|---:|---:|
| Генерация | 11 ток/с | 24 ток/с |
| Чтение промпта | 45 ток/с | 110 ток/с |
| Память (без mmap) | 2.8 ГБ | 1.4 ГБ |

| Операция | Время |
|---|---|
| Урок по алгебре §1 (ru), 6 заданий + 6 слайдов | **4 мин 20 с** (задания 140 с, слайды 120 с) |
| Урок по физике §7 (kk), то же | **7 мин 44 с** (под нагрузкой: параллельно работала видеокарта) |
| Короткий ответ на вопрос | 5–8 с |
| Ответ с RAG | +20–25 с до первого слова (промпт растёт с ~50 до ~1000 токенов) |
| Загрузка учебника (Tesseract) | 6–14 мин на книгу |
| Обучение, 50 примеров (видеокарта) | 65 с + ~1 мин загрузка; пик 3.9 ГБ из 8 |
| Экспорт в GGUF | ~5 мин |

Почему казахский медленнее: ~2 символа на токен против ~2.7 у русского — тот же параграф
на казахском даёт больше токенов и на чтение, и на ответ.

## 3. Прогноз для доски

**Это оценка, а не замер** — процессор доски пока неизвестен. Скорость генерации упирается в пропускную
способность памяти, чтение промпта — в вычислительную мощность. Интерактивный калькулятор с разными
процессорами — на вкладке «Обзор и план».

| Процессор доски | Генерация 4B | Урок ru | Урок kk | Ответ с RAG |
|---|---:|---:|---:|---:|
| как ноутбук (замер) | 11 ток/с | ~4 мин | ~5 мин | ~30 с |
| современный x86 (Core i5/i7) | ~9 ток/с | ~5 мин | ~6 мин | ~40 с |
| бюджетный x86 (Intel N100) | ~5 ток/с | ~9.5 мин | ~11.5 мин | ~1.3 мин |
| ARM (Rockchip RK3588) | ~4.4 ток/с | ~11.5 мин | ~14 мин | ~1.8 мин |

Расчёт: токены промпта ÷ скорость чтения + токены ответа ÷ скорость генерации, токены взяты из наших прогонов.
На ноутбуке фактические уроки шли 4.3 и 7.7 мин, а не 4 и 5: в те моменты машина была занята другими задачами.

Выводы:
- Память — **не проблема**: 4B без mmap занимает ~3 ГБ, остаётся место под систему и интерфейс доски.
- **Короткие ответы** на вопросы — нормально (10–30 с), с RAG — до 1–1.5 мин до первого слова на слабом CPU.
- **Урок целиком «при учителе» — слишком долго.** Решения: готовить урок заранее (учитель выбирает
  параграф накануне), стриминг (текст появляется сразу), меньше слайдов за раз, 2B-модель для слайдов.
- Если слайды должна верстать сама модель (контракт v1 с координатами), это +4–6 мин на урок:
  координаты и стили занимают в 5.6 раза больше токенов, чем смысл слайда.

## 4. Что предстоит

По приоритету — подробнее в плане на вкладке «Обзор и план» (`docs/plan.json`):
1. **Замер на настоящей доске** — все прогнозы времени сейчас держатся на нём.
2. **Контракт с бэкендом:** кто верстает слайды (модель или код), формулы Unicode вместо LaTeX,
   `answer` у теста должен совпадать с одним из вариантов, ход решения у задач.
3. **Реальный датасет** (от нескольких сотен примеров, упор на казахский) → дообучение → сравнение с базой.
4. **Скорость:** стриминг, подготовка урока в фоне. Проверено, что настройки сервера почти не помогают:
   speculative decoding (ngram, встроенная MTP-голова) и два слота дают от −5% до +8%
   (`benchmark/board_speed.md`). Реальные рычаги — короче вывод, 2B для слайдов, подготовка заранее.
5. **Качество:** проверка расчётных задач, RAG по учебникам вместо Википедии, исправление эталонов
   и ручная оценка бенчмарка.
6. **Картинки для слайдов:** вырезать рисунки со сканов (сейчас «картинка» = вся страница).
7. **Остальные учебники 9–11 классов** и установка на доску.
