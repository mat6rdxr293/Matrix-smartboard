## 4. Автооценка (`benchmark/score.py`)

- Судья обращается к любому OpenAI-совместимому серверу (по умолчанию наш llama-server) и возвращает
  JSON `{score: 0|1|2, reason}` по json_schema. Ошибок разбора на 60 ответах не было; оценка — 6.5 мин
  на оба прогона (CPU, 12 потоков).
- Результат — `benchmark/scores_*.csv` (UTF-8 с BOM, открывается в Excel). Колонки `human_score` и
  `human_comment` заполняются вручную и **сохраняются при повторном запуске**. В сводке
  `human_score` имеет приоритет над оценкой судьи (`--summary-only`).
- Сверка судьи с моей ручной проверкой: совпадение в ~26 из 30 случаев. Систематические отклонения:
  - слишком строг к кратким верным ответам: `F = ma` без пояснения и «ньютон (Н)» получили по 1 баллу;
  - слепо следует эталону там, где эталон спорный или устарел (Аңырақай 1729/1730, Конституция 2026).
- Судья оценивает ответы той же модели, поэтому может их завышать. Для решений нужен человек
  или более сильная модель-судья.

## Что упало / ограничения

- **OCR не проверен: tesseract не установлен, а sudo без пароля нет.** `extract_pdf.py` помечает
  страницы `needs_ocr` (причины `no_text_layer` / `bad_encoding`) и умеет распознавать их с `--ocr`,
  но эта ветка ни разу не запускалась на реальном tesseract. Нужно:
  `sudo apt install tesseract-ocr tesseract-ocr-kaz tesseract-ocr-rus tesseract-ocr-eng`,
  затем `python scripts/extract_pdf.py --ocr`.
- Скрипт проверен только на синтетическом PDF из 3 страниц (казахский текст / картинка-скан /
  кириллица в битой кодировке): все три случая распознаны верно. На реальных учебниках пороги
  (`MIN_CHARS=40`, `MAX_BAD_RATIO=0.1`) может понадобиться подстроить.
- По ходу нашёл и исправил в `extract_pdf.py` два своих бага: путь `source` падал для PDF вне
  проекта, а после ошибки оставался недописанный jsonl, который потом пропускался. Теперь запись идёт
  через `.part` и переименование.
- Мелкое: в новой llama.cpp флаг `--no-mmap` убран, вместо него `-lm none`. cmake поставлен через pip в venv.
