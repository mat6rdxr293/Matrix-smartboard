# Кластер серверов Matrix Smartboard (меш-сеть)

Статус: в разработке, ветка `feature/server-mesh`.

## Цель

Несколько серверов в одной школе работают как один:

- любой сервер принимает запись (урок, доска, чат, задания);
- изменения сами расходятся по всем серверам, в том числе через посредника, если два сервера не видят друг друга напрямую;
- доска сама уходит на менее загруженный сервер, а при падении сервера — на живой, без повторной настройки;
- после разрыва сети половины кластера сходятся к одним и тем же данным без ручного вмешательства.

## Журнал изменений

Каждый сервер — узел с постоянным `node_id` (это его Server ID). Каждая запись в базу в той же транзакции добавляет строку в журнал `cluster_log`:

| Поле | Смысл |
|---|---|
| `origin` | узел, где изменение возникло |
| `seq` | номер изменения на этом узле, без пропусков |
| `hlc` | гибридные логические часы `wall_ms-counter-node`, сравниваются как строки |
| `kind` | тип: `school`, `session`, `session_delete`, `room`, `lesson`, `board_op`, `chat`, `doc`, `media` |
| `data` | строка таблицы целиком (JSON) |

Состояние узла описывает **вектор версий** — `{origin: последний seq}`. Синхронизация — pull: узел раз в секунду спрашивает каждого соседа «дай всё, что новее моего вектора». Сосед отдаёт и свои изменения, и чужие, которые получил раньше, поэтому данные доходят через посредников (gossip). Повторное применение изменения ничего не меняет: каждое правило слияния идемпотентно.

## Правила слияния

| Данные | Правило |
|---|---|
| Школы, кабинеты | Неизменяемы, ключ — `id`. Если при разрыве сети в двух половинах создали школу или кабинет с одинаковым именем, побеждает более ранний `(created_at, id)`, а второй получает к служебному имени суффикс `#<id>` и остаётся отдельной записью |
| Сессии входа | Добавляются и удаляются по `token_hash`. Удаление побеждает добавление |
| Уроки | «Последняя запись побеждает» по `hlc`. Правило «один активный урок на кабинет»: из нескольких активных остаётся урок с большим `hlc`, остальные становятся завершёнными. Правило детерминировано, поэтому все узлы приходят к одному результату |
| Операции доски | Неизменяемы, ключ — `(lesson_id, client_operation_id)`. Порядок — см. ниже |
| Чат | Неизменяем, ключ — `(lesson_id, client_message_id)`, порядок `(created_at, origin, seq)` |
| Задания и слайды предметов | Документ целиком, «последняя запись побеждает» по `hlc` |
| Картинки | Файл неизменяем, имя — его содержимое. Узел без файла забирает его у соседа при первом запросе |

### Порядок операций доски

Операции «сдвинуть» и «удалить» ссылаются на штрихи по номеру, поэтому порядок операций урока должен быть **одинаковым на всех узлах** и **сохранять порядок внутри одной доски**.

1. Доска помечает каждую операцию `device_id` (постоянный id устройства) и `client_seq` (растущий счётчик этого устройства).
2. Узел, принявший операцию, ставит ей лампортово время урока: `lamport = max(lamport в уроке) + 1`. Чужие операции приходят со своим `lamport`, и он учитывается в максимуме.
3. Итоговый порядок: для каждого устройства по возрастанию `client_seq` считается `eff = max(lamport, eff предыдущей операции этого устройства)`, затем все операции сортируются по `(eff, device_id, client_seq)`.

На одном сервере это совпадает с прежним порядком прихода. При переключении доски между серверами её операции не перемешиваются, даже если второй сервер ещё не получил операции с первого.

## Доверие

- **Между серверами.** Кластер создаётся на одном сервере, у него появляются `cluster_id` и секрет. Второй сервер присоединяется по одноразовому коду из 8 цифр, который действует 10 минут, и получает секрет. Все запросы между узлами подписаны HMAC-SHA256 этим секретом и меткой времени (окно ±60 с). TLS-ключ каждого узла закреплён в списке узлов.
- **Доски.** Доска уже доверяет своему серверу по закреплённому PIN. Сервер отдаёт по этому защищённому соединению список узлов кластера с их PIN, и доска добавляет их в доверенные. Подделать список может только узел, которому доска и так доверяет.

## Выбор сервера доской

- `/api/status` сообщает нагрузку узла: CPU, очередь ИИ и итоговую оценку от 0 до 1.
- Доска раз в 20 секунд смотрит нагрузку узлов кластера. Если текущий узел загружен больше 0,8, а другой меньше 0,5, доска переключается. Если текущий узел не отвечает, она переходит на самый свободный живой.
- Вход в аккаунт работает на любом узле, потому что сессии синхронизируются. Неотправленные операции доска просто повторяет на новом узле, дубли отсекаются по `client_operation_id`.

## Ограничения первой версии

- Учебники (PDF и их индексы) не синхронизируются: страница учебника берётся у соседа, если на своём узле её нет.
- Старые журналы `board_replay` и история ИИ по предметам остаются локальными.
- Журнал изменений не сжимается.
