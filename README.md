# Matrix Smartboard — ML

ИИ-ассистент учителя для интерактивной доски: офлайн-модель (Qwen3.5-4B → GGUF Q4) и обработка
учебников 9–11 классов (kk/ru/en). Контекст и команды — в `CLAUDE.md`, подробные отчёты — в `REPORT.md`.

**Сценарий:** учитель один раз загружает PDF учебника → доска его обрабатывает (~20 мин) →
учитель выбирает параграф → ИИ генерирует задания и текст для шаблонной презентации.

## Апдейты

Журнал автономной работы: время, что сделано, что получилось.

### Апдейт 1 — 01:25
Старт автономной сессии (~1 час). План:
1. Распознать все три учебника через Tesseract (быстрый рабочий текст, как было бы на доске).
2. Запустить на GPU распознавание казахской физики моделью со зрением (Qwen3.5-4B) — качественный текст
   с формулами в LaTeX, с возможностью продолжить после остановки. Работа долгая, пусть идёт в фоне.
3. Разметка «параграф ↔ страницы» по распознанному тексту.
4. Прототип `lesson.py`: параграф → задания + слайды (JSON), замер времени на CPU в 4 потока.

Учебники в `textbooks/`: история Казахстана 11 (ru, 165 с.), алгебра ЕМН 11 (ru, 254 с.),
физика ЕМН 11, 1-бөлім (kk, 240 с., пометка «Жоба»). Все три — сканы ~95 dpi с okulyk.kz.

### Апдейт 3 — 01:43
- **Tesseract по трём учебникам готов** (`data/raw/`): история 165 стр. — 6 мин, алгебра 254 стр. — 12.5 мин,
  казахская физика 240 стр. — 13.7 мин (три книги параллельно, по 4 потока). **В бюджет «~20 минут на загрузку»

- Новый скрипт `scripts/sections.py`: разметка «параграф ↔ страницы» по тексту. Tesseract искажает «§»

  **Результат: алгебра 28/28, физика 41/41, история 11 сдвоенных параграфов (§1-2 … §21-22) — без пропусков.**
  Выход: `data/sections/*.json` (номер, название, страницы).
- Распознавание физики моделью со зрением идёт в фоне: ~25 с/стр., готово ≈ к 03:30.

### Апдейт 4 — 02:07
- Новый скрипт **`scripts/lesson.py`** — главный сценарий доски: «книга + §N → задания + слайды» (JSON по схеме)
  через llama-server (CPU, 4 потока, без mmap). Текст берётся из распознавания моделью со зрением, если оно
  есть для всех страниц параграфа, иначе из Tesseract. Результаты: `data/lessons/*.json`.
- Проверено на **казахской физике, §7 «Айнымалы ток генераторы»** (стр. 46–52):
  - Казахский грамотный, тесты осмысленные, формулы в LaTeX верные ($\Phi = BS\cos\alpha$, $\mathcal{E}_m = BS\omega$).
  - **Расчётные задачи ненадёжны:** в одном прогоне задача была с бессмысленными единицами и неверным ответом,
    в другом — сомнительная формула $f = n/p$. Ответы к расчётам нужно проверять (или помечать «проверьте»).
  - Нашёл и закрыл **зацикливание** (`\bar{\bar{\bar{…` до конца слайда): штраф за повторы, лимиты длины полей
    в JSON-схеме, автопроверка ответа и повтор с другим seed.
- **Время — главная проблема:** ~7.5 мин на урок (задания + 6 слайдов).
  - 6000 символов казахского текста ≈ 2700–2900 токенов (казахский дорогой: ~2 символа на токен) → чтение ~80 с.
  - Генерация: задания ~890 токенов (~2 мин), слайды ~1500 токенов (~4 мин).
  - Слайды после первого запроса читают параграф из кэша сервера (2249 из 2747 токенов) — это работает.
  - Замер под нагрузкой (параллельно шло распознавание на GPU): генерация 6.5–7 ток/с вместо обычных 11,
    на свободной машине будет ~5 мин. На процессоре доски, скорее всего, медленнее.
- Идеи, как ускорить (на следующий раз): стриминг (учитель видит текст сразу), меньше слайдов/заданий за раз,
  подготовка урока заранее в фоне (учитель выбирает параграф накануне), модель 2B для слайдов.
- Сервер остановлен. **Распознавание физики моделью со зрением продолжает работать** (готово 72/240 стр., ≈ 80 мин).

### Итог часа
Весь сценарий «PDF → текст → параграфы → задания и слайды» собран и работает на реальных учебниках, включая
казахский. Узкие места: скорость генерации на CPU и правильность расчётных задач. Подробности — в апдейтах выше.
