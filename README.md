# Школьная интерактивная доска

Приложение для уроков с интерактивной доской, заданиями, презентациями и ИИ-ассистентом. Одна школа регистрирует общий аккаунт, а каждая доска привязывается к своему кабинету. У кабинетов независимые истории уроков.

## Возможности

- самостоятельная регистрация школы по названию и паролю;
- выбор существующего кабинета или создание нового при первой настройке доски;
- отдельные шаги выбора класса и предмета;
- предметы с учётом школьной программы Казахстана;
- восстановление незавершённого урока после обновления страницы;
- архив уроков каждого кабинета;
- интерактивные координатные плоскости с несколькими функциями, цветами, подписями осей, перемещением и изменением размера;
- единая история штрихов, графиков, отмены, повтора и очистки вместе с перепиской с ИИ;
- светлая и тёмная темы, которые сохраняются между запусками;
- адаптивная двухуровневая панель существующих инструментов доски.

## Графики на доске

Выберите инструмент **«График»** и нажмите на доску. Появится координатная плоскость: её можно перемещать, менять размер, масштабировать и дополнять функциями разных цветов. Подписи `x` и `y` редактируются нажатием, поэтому для физики можно указать, например, `t, c` и `v, м/с`.

Поддерживаются:

- арифметика, степени и неявное умножение: `x^2 - 4x + 3`, `2x + 1`;
- тригонометрия: `sin`, `cos`, `tan`/`tg`, `cot`/`ctg`, `sec`, `csc`;
- обратные и гиперболические функции: `asin`/`arcsin`, `acos`, `atan`, `acot`, `sinh`, `cosh`, `tanh`, `coth`;
- логарифмы и экспонента: `ln`, `log`/`lg`, `log2`, `exp`;
- корни и модуль: `sqrt`, `cbrt`, `abs`, а также `floor`, `ceil`, `round`, `sign`;
- константы `pi` и `e`.

Аргументы тригонометрических функций задаются в радианах. Логарифм по произвольному основанию записывается как `ln(x)/ln(b)`. Выражения вычисляются локальным безопасным парсером без `eval` и сетевых сервисов.

Переключатель темы находится в **Настройки → Оформление**. Выбранная тема применяется ко всем экранам и сохраняется в браузере.

## Предметы по классам

- 1–2 классы: математика, естествознание, казахский и русский языки;
- 3–6 классы: те же предметы и английский язык;
- 7–11 классы: алгебра, геометрия, физика, химия, биология, география, казахский, русский и английский языки.

Матрица составлена по типовым учебным программам и учебному плану Казахстана: [приказ об учебных программах](https://old.adilet.zan.kz/rus/docs/V2200029767), [перечень программ 1–11 классов](https://www.gov.kz/memleket/entities/kostanai-bilim/documents/details/533222), [типовые учебные планы](https://www.adilet.zan.kz/rus/docs/V2200030654).

## Запуск

### macOS

```bash
chmod +x scripts/dev.sh
./scripts/dev.sh
```

Откройте `http://localhost:5174`. Скрипт запускает FastAPI на порту `8001` и Vite на порту `5174`.

### Windows

```powershell
scripts/dev.ps1
```

### Android

Android-приложение находится в `frontend/android` и собирается через Capacitor. При первом запуске пользователь выбирает RU/KK/EN, затем приложение ищет серверы Matrix Smartboard через DNS-SD/mDNS (`_matrixboard._tcp.local`). Если multicast в hotspot/guest-сети не проходит и mDNS не находит сервер, Android автоматически проверяет текущие приватные `/24` подсети по HTTPS-порту `8443` и добавляет только хосты, чей `/api/status` идентифицирует Matrix Smartboard; перед подключением по-прежнему выполняется проверка TLS pin/serverId. Адрес также можно указать вручную; для адреса без схемы автоматически используется `https://...:8443`.

Локальный сервер использует собственную постоянную TLS identity и может иметь понятное имя, например `Главный сервер` или `Сервер №1`. Имя публикуется через mDNS и возвращается в `/api/status`, поэтому в Android-списке отображается имя, а не технический идентификатор.

При первом подключении APK показывает fingerprint публичного ключа и после подтверждения закрепляет (pins) его. При смене IP сертификат может быть перевыпущен с тем же ключом, поэтому server ID и pin не меняются. На следующих запусках приложение сначала проверяет последний адрес, затем при необходимости до 6.5 секунд ищет тот же `serverId` через mDNS. Новый endpoint принимается только после проверки прежнего pin. Если подключиться не удалось, вместо сырого `Failed to fetch` показывается диагностика: сохранённый адрес, поиск в сети, identity и HTTPS/backend. HTTP в Android-сборке отключён.

В режиме автоматической настройки приложение проверяет SSH fingerprint, определяет ОС, позволяет задать имя сервера, загружает проект из GitHub, создаёт Python-окружение и запускает HTTPS на порту `8443`. На Debian/Ubuntu backend устанавливается как systemd-служба, на macOS — как launchd LaunchDaemon, на Windows — как задача Task Scheduler под `SYSTEM` с автозапуском при старте системы. Для Windows также автоматически создаются правила Windows Firewall для HTTPS и mDNS. По желанию на всех поддерживаемых ОС настраиваются Ollama, Qwen 2.5 7B и Qwen 2.5 VL 3B для локальных AI/OCR. Пароль SSH используется только во время настройки и не сохраняется.

На Windows должен быть включён OpenSSH Server, а SSH-аккаунт должен входить в локальную группу `Administrators`. Установщик работает через Windows PowerShell, сохраняет данные и TLS identity в `C:\ProgramData\MatrixSmartboard`, а сам backend — в `C:\ProgramData\MatrixSmartboard\app`. Если Python 3.11+ или Ollama отсутствуют, установщик пытается поставить их через `winget`.

После подключения в настройках доступен экран `Сервер`: ОС и hostname, CPU/RAM/диск/GPU, latency, состояние backend/Ollama, установленные модели, подробные журналы, перезапуск служб, скачивание недостающих Qwen-моделей, backup/restore и проверка обновлений. Обновление выполняется отдельным системным helper: старая версия сохраняется, новая проходит HTTPS health-check, а при ошибке автоматически выполняется rollback. Backup содержит БД школ/уроков, данные доски, медиа, конфигурацию и TLS identity, поэтому архив следует хранить как чувствительный файл.

Во время урока операции доски сохраняются в локальную очередь. При потере сервера интерфейс показывает `Нет связи`, работа с доской продолжается локально, а после восстановления адреса/сети очередь автоматически синхронизируется. Локальные изменения заданий/презентаций также остаются в аварийном localStorage backup до успешного autosave на сервер.

Для ручного production-запуска сервера на macOS/Linux используйте `scripts/run-prod.sh`, на Windows — `scripts/run-prod.ps1`. Dev-скрипты по-прежнему могут использовать HTTP localhost.

```bash
cd frontend
npm run android:sync
cd android
./gradlew assembleDebug
```

Готовый тестовый APK: `frontend/android/app/build/outputs/apk/debug/app-debug.apk`.

### Локальный ИИ: Qwen 2.5 через Ollama

Для текущей локальной конфигурации используются две модели:

- `qwen2.5:7b` — основной ИИ для решения, подсказок, проверки и работы с инструментами;
- `qwen2.5vl:3b` — мультимодальная модель для OCR и распознавания записи с доски.

Установите Ollama, загрузите обе модели и оставьте Ollama запущенным:

```bash
ollama pull qwen2.5:7b
ollama pull qwen2.5vl:3b
```

Скопируйте `backend/.env.example` в `backend/.env`. Нужные значения уже указаны в примере:

```env
AI_BASE_URL=http://localhost:11434/v1
AI_MODEL=qwen2.5:7b
OCR_BASE_URL=http://localhost:11434/v1
OCR_MODEL=qwen2.5vl:3b
```

Для локального режима `OPENAI_API_KEY` не нужен.

## Данные

По умолчанию школы, кабинеты и уроки находятся в `backend/app/data/practice.db`. Путь можно изменить через `PRACTICE_DB_PATH`. TLS identity хранится отдельно в `SERVER_IDENTITY_DIR`; приватный ключ не должен копироваться в APK или Git. Для переноса сервера с сохранением его identity нужно переносить и базу, и каталог identity через защищённый backup.

Секреты задаются в `backend/.env`; пример находится в `backend/.env.example`. Файлы базы, identity, окружения, сборки, медиа и секреты исключены из Git.

## Структура

- `backend/` — FastAPI, SQLite, алгоритмы и интеграция ИИ;
- `frontend/` — React, Vite и Tailwind CSS;
- `scripts/` — команды запуска, сборки и проверки;
- `docs/` — спецификация и план реализации.
